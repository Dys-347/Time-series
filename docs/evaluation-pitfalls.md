# 时序预测评估的陷阱：哪些是作弊，哪些只是偏乐观

> 2026-10-14 建立。核心判断：**先分清"偷看了答案"和"评估方式偏乐观"，再谈结果可不可信。**
> 本文第 3 节是我们自己跑的实验，第 2 节是对 Time-Series-Library 标准切分代码的检查，其余部分整理自文献。

## 1. 判断标准：预测那一刻，这个信息能不能知道？

预测时只能用"那一刻已经发生的数据"。凡是用了当时还不可能知道的信息，就是**泄漏（作弊）**；没有用到未来信息、但让结果看起来更好的做法，属于**偏乐观**。

### 1.1 合法的做法（常被误以为作弊）

| 做法 | 为什么合法 |
|---|---|
| 用训练集的均值和方差做标准化 | 训练时就能知道 |
| RevIN 用输入窗口自己的均值和方差 | 只用了过去的数据 |
| 测试窗口的输入有一部分落在验证集时间段 | 预测时历史本来就是已知的 |
| 模型训练完固定不动，只做前向预测 | 没有用到任何未来答案 |

### 1.2 真正的泄漏

| 做法 | 问题 | 出处 |
|---|---|---|
| 上线后边预测边学，但没等标签到达 | 预测未来 H 步，完整答案要 H 步后才有。提前用来更新模型，就是偷看答案 | [Training on the Future](https://arxiv.org/abs/2610.12232)（2026-10）；[Proceed](https://arxiv.org/abs/2412.08435)（KDD 2025） |
| 先切滑动窗口，再划分训练集和测试集 | 训练样本的答案会跨进测试期 | [Hidden Leaks in Time Series Forecasting](https://www.researchgate.net/publication/398475488_Hidden_Leaks_in_Time_Series_Forecasting_How_Data_Leakage_Affects_LSTM_Evaluation_Across_Configurations_and_Validation_Strategies) |
| 用全部数据（含测试集）拟合标准化或分解 | 测试期的统计量混进了训练；EMD 等分解若作用于整条序列，同样会泄漏 | — |
| 基础模型的预训练数据包含别人的测试集 | 测试集被"见过" | [Rethinking Evaluation in the Era of TSFMs](https://arxiv.org/abs/2510.13654) |

### 1.3 不是作弊，但让结果偏乐观

| 做法 | 问题 | 出处 |
|---|---|---|
| 在测试集上调超参数（输入长度、学习率、层数） | 等于看过答案再选答题方式；论文附录里"每个数据集一套超参数"常常就是这么来的 | — |
| 测试时丢掉最后一个不满批次（drop_last） | 结果随 batch size 变化，部分测试样本没被评估 | FITS、TFB 指出；见 [SegRNN 的修正说明](https://github.com/lss-1138/SegRNN) |
| 只跑一个 seed，不报置信区间 | 1–2% 的"超过 SOTA"可能只是随机波动 | [There Are No Champions](https://arxiv.org/abs/2502.14045)（TMLR 2026） |
| 把步长为 1 的重叠窗口当成独立样本 | 相邻窗口大部分重合，有效样本远少于窗口数，误差范围被低估 | — |
| 自定义评估函数（只取部分变量、截断负值等） | 结果无法和其他论文比较 | — |

更系统的批评见：[Position: Current Benchmarking Hinders Real Progress](https://arxiv.org/html/2512.22702v2)（ICML 2026 position paper）。

## 2. 检查：Time-Series-Library 的标准切分有没有"最后一段"的问题

**问题**：在时刻 T，最近 H 步的数据只能当输入，不能当答案（它们的未来还没发生），所以这一段凑不出完整的训练样本。评估时如果假装模型学到了这一段，就是作弊。

**检查结果（读 `data_provider/data_loader.py`）**：没有这个问题。以 ETTh1 为例：

```
时间轴（小时）：
0 ────────── 8640 ────── 11520 ────── 14400
   训练集（12个月）  验证集（4个月）  测试集（4个月）
```

1. 每个切分内部样本数 = 长度 − 输入长度 − 预测长度 + 1，所以训练样本的答案不会越过训练集末尾。训练集最后 H 步只当过答案。
2. 验证集只用于早停，不参与训练。模型测试时，离它学过的最新数据隔了 4 个月，比现实部署还保守。
3. 测试窗口的输入从测试期起点往前 96 步开始，用的是已知历史，合法。
4. 标准化只在训练集上拟合（`scaler.fit(train_data)`）。

Electricity 等 `Dataset_Custom` 数据集按 7:1:2 切分，逻辑相同。当前版本测试时 `drop_last = False`。

## 3. 实验：等标签到了再修正，有没有用？

### 设置
- **模型**：4 个冻结模型（d_model=64，输入 96，预测 96，单 seed，5 epoch）：PatchTST/ETTh1、iTransformer/ETTh1、PatchTST/Electricity、PatchTST/ETTh2（审计论文中漂移最强的数据集）。
- **修正器**（无需调参，每个变量 × 每个预测步单独维护）：
  - EWMA 偏差库：用指数滑动平均估计残差偏差，α ∈ {0.01, 0.003, 0.001}，取中位数。
  - RLS 仿射库：递归最小二乘拟合 y ≈ a + b·ŷ，遗忘因子 λ ∈ {0.99, 0.995, 0.999}，取中位数。
- **标签规则**：预测起点 s 的完整答案，到第 s+d 步才能用于更新。d = H（96）是最小合法延迟；另测 2H、4H。d = 1 是**作弊版**，相当于提前看到未来 95 步。
- **评估**：标准化空间，全部变量，全部滑动窗口；95% 置信区间用 moving-block bootstrap（块长 2H，1000 次）。

### 结果（测试集，相对冻结模型的 MSE 变化；负数 = 变好）

| 模型 | RLS 作弊版 | RLS 延迟 H | EWMA 作弊版 | EWMA 延迟 H |
|---|---|---|---|---|
| PatchTST / ETTh1 | **−6.1%** | +8.2% [+4.0, +12.5] | −1.0% | +2.8% [+1.7, +3.9] |
| iTransformer / ETTh1 | **−8.8%** | +5.8% [+0.2, +11.4] | −2.3% | +2.0% [−0.4, +4.0] |
| PatchTST / ETTh2 | **−21.1%** | +9.6% [−2.9, +17.0] | −4.4% | +6.6% [+2.7, +10.0] |
| PatchTST / Electricity | **−11.4%** | +20.4% [+1.5, +54.4] | −3.0% | +3.2% [+1.6, +5.1] |

### 发现
1. **作弊版全部变好，按真实规则全部变差或不显著。** 不严格控制标签延迟，就会得出"自适应能降低 6–21% 误差"的错误结论。与审计论文的结论一致（他们报告泄漏会把增益夸大最多 110%）。
2. **漂移最强的 ETTh2 上也没用。** 问题不在"漂移不够多"，而在于等标签到了再修正，修正已经过时。
3. **验证集和测试集结论相反。** 验证集上 RLS 按真实规则也能降低 4–7% 的误差，测试集上却变差。用验证集决定"要不要上自适应"会做出错误决定。原因可能是验证集紧接训练集、系统性偏差较稳定，测试期的偏差则在变化。这是推测，未单独验证。

### 局限
只测了两种简单修正器，不是 TAFAS、PETSA 等已发表方法；单 seed、5 epoch，只测了预测长度 96；RLS 实现与审计论文不同，不能直接比较。

## 4. 写论文时的自查清单

1. 超参数只用验证集选，测试集只在最后跑一次。
2. 测试时 `drop_last = False`。
3. 至少 3 个 seed，报均值和标准差。
4. 置信区间用 block bootstrap，不把重叠窗口当独立样本。
5. 同时报标准化 MSE、原始量纲 MSE，以及相对 persistence 的提升。
6. 涉及在线更新时，标签延迟 ≥ 预测长度，并同时报告冻结模型作为对照。
7. 分解、标准化等预处理只用当时可得的数据。
