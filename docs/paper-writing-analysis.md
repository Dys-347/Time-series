# 论文写法拆解

> 2026-10-13 建立。核心判断：**同样的方法，换一种讲法，审稿人的感受完全不同。**
> 这里拆的是"怎么讲"，不是"做了什么"。方法本身的分析见主站条目和 [北大组分析](pku-ying-group.md)。
> 每条拆解都要能对应到原文的具体段落或代码；只读过摘要的论文，不做写法判断。

## 1. 拆解框架（每篇论文按这 7 项填）

| 维度 | 要回答的问题 |
|---|---|
| ① 问题命名 | 有没有给问题起一个新名字？这个名字把什么旧现象重新包装了？ |
| ② 知识来源 | 方法借自哪个领域？原文有没有点名这个领域？用什么词替代了来源领域的说法？ |
| ③ 对手设定 | 把已有方法归纳成什么"共同假设"？这个归纳是否准确，还是为了衬托自己而简化？ |
| ④ 叙事动词 | 用"reformulate / rethink / from X to Y"这类词，把增量改进讲成视角转换了吗？ |
| ⑤ 证据结构 | 除了 benchmark 刷分，有没有机制实验（合成数据、分层分析、可视化）把故事讲成因果？ |
| ⑥ 理论的角色 | 定理是方法有效的主要证据，还是解释性点缀？假设强不强？ |
| ⑦ 局限的写法 | 承认了什么短板？是正面解决、换个说法绕过去，还是留作"未来工作"？ |

最后一栏写**"可学的"**和**"要警惕的"**：前者是我们写论文时能用的手法，后者是审稿时要追问的地方。

## 2. 案例：AOSNet（东南大学，arXiv:2606.06010）

> 阅读深度：HTML 全文（方法、实验、讨论），未读代码。

| 维度 | 拆解 |
|---|---|
| ① 问题命名 | 造了新词 **NRP（non-rigid periodicity，非刚性周期）**，并拆成三个子问题：周期幅度变化、周期对齐漂移、周期长度伸缩。这三件事在信号处理里就是调幅、调相、调频（AM/FM），但原文没有这样叫 |
| ② 知识来源 | 核心工具是解析信号和 Hilbert 变换，引用的是信号处理的经典文献（瞬时频率的估计与解释）。**全文没有提语音或通信**。来源领域的"瞬时频率、包络"被改称为"oscillatory-state descriptors（振荡态描述符）" |
| ③ 对手设定 | 把 CycleNet、TQNet、频域方法、分解方法统一归纳为 **"把周期当作固定模板"**。归纳有道理，但把差异很大的方法压成一个共同弱点，正好衬托"自适应对齐" |
| ④ 叙事动词 | "reformulates periodic forecasting **from** fixed template matching **to** adaptive oscillatory-state alignment"：把"加一个 Hilbert 特征 + 门控"讲成视角转换 |
| ⑤ 证据结构 | 用 RQ1–RQ5 组织实验。最有说服力的是合成数据：单独控制幅度变化、对齐漂移、长度变化，显示**周期变形越强，优势越大**。这把"效果好"讲成了"因为解决了 NRP"。另外加了云计算负载数据，用"容量规划、自动扩缩容"说明为什么要快 |
| ⑥ 理论的角色 | 没有定理，靠机制实验和可视化支撑 |
| ⑦ 局限的写法 | 坦白承认真实序列"不一定是窄带、单分量的"，Hilbert 量不是严格物理量。处理方式是**换个说法绕过去**：称它们为"结构描述符"，由门控决定信多少，没有做分频段来正面解决 |

- **可学的**：给问题起名并拆成可控的子问题；用合成数据做"强度越大、优势越大"的剂量曲线；找一个真实场景（云负载）说明效率为什么重要。
- **要警惕的**：NRP 和经典调幅/调相/调频是什么关系，原文没讲；"描述符不是物理量"等于承认相位和频率的含义不清，却仍以它们为核心卖点。

## 3. 案例：北大应翔华组（OLinear / vLinear / HLinear）

> 依据：主站条目、[北大组分析](pku-ying-group.md)，以及 HLinear 读码结果。

| 维度 | 拆解 |
|---|---|
| ① 问题命名 | HLinear："从'数值'到'振荡态'"；vLinear："final-series oriented（面向最终序列）" |
| ② 知识来源 | HLinear 的 Hilbert 同样来自信号处理，同样不提语音。OLinear 的 OrthoTrans 本质是对相关矩阵做特征分解（接近 PCA/KL 变换），被包装为"数据自适应正交变换" |
| ③ 对手设定 | 批评傅里叶和小波"用固定基"；把 attention 的价值归结为"归一化的混合形式"，从而论证线性层可以替代 |
| ④ 叙事动词 | 题目直给："Simple yet effective"、"Powerful" |
| ⑤ 证据结构 | 主要靠规模：benchmark 数量逐篇增加（18 → 22，124 种设置）。每篇都声称模块可以即插即用，并做插入实验 |
| ⑥ 理论的角色 | 每篇配 1–2 个定理（多样性/梯度流、秩、MLE 最优），假设偏强（如 Laplace + 一阶 Markov），属于解释性点缀 |
| ⑦ 局限的写法 | 读码发现的情况：HLinear 的"Hilbert 引导"实际是**加法注入 + 全局标量门**，"guided"有包装成分；混合矩阵形状与变量数绑定，即插即用在变量数变化时需要重新初始化。这些在论文里着墨很少 |

- **可学的**：连续多篇沿一条线推进，每篇回答上一篇的问题；即插即用降低别人试用门槛；用大量 benchmark 堵住"挑数据集"的质疑。
- **要警惕的**：定理不能当作方法有效的主要证据；"guided""plug-and-play"这类说法要对照代码核实。

## 4. 跨论文的共同规律（目前 2 组样本，仅供参考）

1. **借来的工具不点名来源领域。** 两家都用 Hilbert，都只说"解析信号"，不说语音或通信。好处是读起来像时序领域的原生问题；代价是没有吸收来源领域已经解决的问题（例如语音里先分频段再求包络，正好能解决两家都承认的"非单分量"问题）。
2. **新名字 + 子问题拆解 + 合成实验**，是把增量改进讲成新视角的标准组合。
3. **短板多用改名或"未来工作"处理**，很少正面解决。这些地方就是后续工作的切入点。

## 5. 维护规则

- 每加一篇，按第 1 节的 7 项填写，并注明阅读深度（摘要 / 全文 / 代码）。
- 写法判断要对应原文段落或代码行，不凭印象。
- 区分"包装"和"误导"：换说法、起新名字是正常的写作选择；只有在原文与代码、实验不一致时，才记为问题。
